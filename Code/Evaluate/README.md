# Crossword Evaluation

`evaluate_outputs.py` evaluates the original Section 3.2 raw model
outputs and outputs generated by the local inference scripts. It applies the
same answer post-processing as `Code/LLM-Inference/src/postprocess.py`, then
computes exact match, answer-length violations, embedding cosine similarity,
call counts, token usage, and API cost where available.

Pass the output directory and dataset explicitly. The output directory is
searched recursively for matching `*__fewShot_*.json` files:

```powershell
python Code\Evaluate\evaluate_outputs.py `
  --output-dir "Data\Raw Outputs\Section 3.2" `
  --dataset nyt `
  --name paper_baseline
```

`--name` is optional and controls the result filename. With the example above,
the files are `Result/evaluation_paper_baseline_nyt.csv` and `.json`. If omitted,
the output directory's final folder name is used.

For your inference results:

```powershell
python Code\Evaluate\evaluate_outputs.py `
  --output-dir "Code\LLM-Inference\outputs" `
  --dataset nyt
```

The `--dataset` choices are `nyt`, `cryp` (or `cryptonite`), and `init`.
Use `--source paper` or `--source user` to override automatic source detection.

Results are written to the hard-coded repository `Result/` directory, with
names based on the input directory and dataset, such as
`evaluation_outputs_nyt.csv` and `evaluation_outputs_nyt.json`.

## User log directory

`Code/LLM-Inference/logs/` is the directory where `main_modified.py` writes
the per-call `*_calls.jsonl` and aggregate `*_summary.json` files. The evaluator
uses these to obtain actual attempted call counts, retries, token totals, and
estimated API cost. It does not contain model answers; those are read from the
directory supplied with `--output-dir`.

If logs are stored elsewhere, pass their location with `--log-dir`. Without
matching logs, the evaluator assumes one call per output answer and reports
cost as unavailable. Paper calls are likewise counted as one call per raw
answer; paper billing metadata is not included.

## Semantic cosine score

The evaluator uses the pre-trained `glove-wiki-gigaword-50` word vectors by
default. Gensim downloads and caches the model on first use; the model can be
changed with `--embedding-model`. Since crossword answers are stored as
concatenated letters, `wordninja` segments answer strings before their word
vectors are averaged.

For each answer pair, cosine similarity is mapped linearly to a 0-100 score:

```text
pair score = (cosine similarity + 1) * 50
semantic score = sum(pair scores) / number of pairs with both vectors
```

The reported `semantic_cosine_score_0_100` is the mean across covered pairs;
`semantic_embedding_coverage_pct` reports the percentage of evaluated clues
for which both answers have vectors. Out-of-vocabulary pairs are excluded from
the mean rather than treated as dissimilar. This is a continuous embedding
similarity score, not a thresholded accuracy or human judgment.
